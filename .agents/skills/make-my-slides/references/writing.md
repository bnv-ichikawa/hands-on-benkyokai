# スライドの書き方

内容（`deck.json`）に何をどう書くかの基準です。JSON の形式は [tools/make-pptx/README.md](../../../../tools/make-pptx/README.md) にあります。ここには書き写しません。

## 分量の目安

持ち時間から枚数を決め、ユーザーに伝えます。

| 持ち時間 | 目安の枚数 |
| --- | --- |
| 5分 | 8〜12枚 |
| 10分 | 15〜20枚 |
| 15分 | 20〜28枚 |
| 30分 | 35〜45枚 |

1枚を30〜60秒で話せる量に収めます。質疑を含む場合は少ない側に寄せます。目安を超える情報量なら、削る候補を先に相談します。

## 1枚に入れる量

公式レイアウトのプレースホルダーには決まった幅があります。**超えると折り返して重なります。**

| 対象 | 上限 |
| --- | --- |
| 表紙の `title` | **16文字**（2行まで） |
| 本文の `title` | 24文字（1行） |
| `subtitle` / `lead` | 1文・50文字 |
| `bullets` の項目数 | 5項目 |
| `bullets` の1項目 | 40文字 |
| 表の行数 | 6行 |
| 表の列数 | 4列 |

上限を超えたら、枚を分けるか削ります。**文字を小さくして詰め込みません。**

表紙のタイトルは幅 401pt しかありません。3行になると副題に重なるので、ここだけは特に厳しく守ります。

## 構成の既定

導入 → 課題 → 内容 → まとめ。ここから外れる構成にする場合は、理由を一文添えてユーザーに確認します。

```text
 1  表紙                cover
 2  アジェンダ           content
 3  なぜこの話をするか    content
 4  （章扉）            section
 5〜 内容               content
 n-1 出典と未確認事項    content
 n  締め                closing
```

## 文の書き方

- タイトルを上から読むだけで話の流れが分かるようにする
- `bullets` だけで埋めない。`lead` に伝えたい一文を必ず置く
- 体言止めと文末を揃える。1枚の中で混ぜない
- 数字と固有名詞は材料にあるものだけを書く

## 事実・判断・提案を混ぜない

スライドの上では次を区別します。

| 種類 | 書き方 |
| --- | --- |
| 確認できた事実 | そのまま書き、出典の枚で場所を示す |
| ユーザーの判断・経験則 | 「〜と判断している」と主体を書く |
| AI からの提案 | 構成案の段階で「AIからの提案」と明示し、採用の可否を聞く |
| 未確認 | `未確認` または `（要確認）` と書く |

材料に無い事実を追加しません。未確認の内容を断定しません。ここでの材料とは、指定されたメモ、またはユーザーから聞き取った内容です。

## 出典と未確認事項の枚

締めの前に、出典と未確認事項をまとめた枚を置きます。

```json
{
  "type": "content",
  "title": "出典と未確認事項",
  "lead": "この資料の根拠と、確認できていないことを分けておく。",
  "bullets": [
    "出典: second-brain/areas/example.md",
    "出典: 本人からの聞き取り（2026年MM月DD日）",
    "未確認: 裏付けを取っていない項目"
  ]
}
```

元になるメモがある場合はその場所を、聞き取りだけで作った場合は「本人からの聞き取り（日付）」と書きます。

聞き取りだけで作った資料は、裏付けのある事実と本人の記憶が混ざりやすくなります。数字や固有名詞は、特に断定していないかを見直します。

この枚を共有先に見せたくない場合は、ユーザーへ確認したうえで枚から外し、内容は別途テキストで渡します。

## 図を入れる

図は**画像として貼ります。** JSON の `image` に画像のパスを書きます。

```json
{ "type": "content", "title": "全体の流れ", "lead": "メモが資料になるまで。", "image": "outputs/flow.png" }
```

図そのものは、ユーザーが用意したものか、別の手段で作った画像を使います。**1枚に図は1つまで**です。図を入れた枚は `bullets` を3項目までに抑えます。

## 発表者用メモ

スライドに載せないが話したいことは、**PowerPoint のノート欄**に自分で書きます。生成時には入らないため、必要なら渡すときにその旨を伝えます。

## 仕上げはPowerPointでよい

字間の微調整、図形の追加、アニメーションなどは PowerPoint 側で行うほうが早いです。

**ユーザーが PowerPoint で仕上げ始めたら、そこから先は pptx が正本になります。** JSON から作り直すと上書きされるため、作り直す前に必ず確認します。

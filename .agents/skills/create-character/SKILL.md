# Create Character

新しいキャラクターの下書きを作る。設計をすぐに確定せず、ユーザーに質問して一緒に詰める。

## 前提

- 現在割り当てられているキャラクターがある場合は `AGENTS.md` を読む。
- 作成先はリポジトリのルートの `private/ai-characters/<名前>.md`。フォルダがなければ作る。
- アイコン画像を使う場合は `assets/characters/<表示名>-icon.png` に置く。
- 見出しは `##` から始める。`#` は使わない。
- キャラクターファイルには、会話でそのまま使える内容だけを書く。

## 進め方

### 1. 作りたいキャラを聞く

まず1行で、どんなキャラクターを作りたいかを聞く。すでに方向性が書かれていれば、それを踏まえてもよい。

必要なら、ファイル名や表示名が曖昧なときだけ2つまで候補を出す。

### 2. 最初に画像の希望を聞く

人物像の質問に入る前に、キャラクター画像が要るかを聞く。

- 画像が要るなら、既存作品のキャラでも架空のキャラでも、まずネット検索を試す。
- 実在する既存キャラなら、公式サイトや信頼できる紹介ページを優先して探す。
- 架空キャラや既存画像が見つからない場合は、必要に応じて画像生成も使う。
- 画像を用意できたら、32x32px のアイコン画像を `assets/characters/<表示名>-icon.png` として保存する。
- 画像が不要なら、この工程は省く。

### 3. 第1ラウンドの質問

ここでは人物像を決める。最大5問。できれば1回の質問で2〜3項目をまとめて聞く。

1. このキャラクターは、ユーザーにとってどんな存在か。
2. どんな話し方をするか。
3. どんな性格か。
4. どのくらいの知識や経験を持つか。
5. どんな場面で使いたいか。

### 4. 第2ラウンドの質問

第1ラウンドの答えを受けて、必要なら追加で最大5問だけ聞く。

1. 迷ったときにどう判断するか。
2. 強めに言う場面と、やさしく言う場面の切り分け。
3. 口調の細かい癖。
4. やってほしいこと、やってほしくないこと。
5. 他キャラとの関係性が必要か。

### 5. 下書きを作る

`private/ai-characters/<名前>.md` を新規作成する。1行目は必ず `## 現在のキャラクター: <表示名>` にする。

画像を使う場合は、冒頭に次のセクションを必ず入れる。

```markdown
## キャラクター画像

各回答の冒頭に、32×32pxの次の画像を1回表示する。

![<表示名>](../../assets/characters/<表示名>-icon.png)
```

ドラえもんなら、次のように書く。

```markdown
## キャラクター画像

各回答の冒頭に、32×32pxの次の画像を1回表示する。

![ドラえもん](../../assets/characters/ドラえもん-icon.png)
```

画像パスは、作成先の `private/ai-characters/` から見た相対パス `../../assets/characters/<表示名>-icon.png` で書く。

本文の最小構成は次のとおり。

```markdown
## 現在のキャラクター: <表示名>

### ひとことで言うと
### 性格
### 話し方
### やること
```

この4セクションは必ず入れる。必要なら次も追加してよい。

- `### このキャラクターがしないこと`
- `### 代表的な関係性`
- `### 使いどころ`
- `### 参考にした情報`

### 6. ユーザーに渡す

完成したら、下書きが `private/ai-characters/` に入ったことを短く伝える。

## 文章のルール

- 日本語で書く。
- 文字数は長すぎないようにする。
- 断定しすぎず、でも曖昧すぎない。
- そのキャラクターらしい一貫した口調にする。
- ユーザーが使いやすいように、実際の会話で使える文にする。

## やってはいけないこと

- `private/ai-characters/` の外にキャラクターの本体を置くこと
- 画像が要るかを確認せずに決め打ちすること
- 既存キャラなのに画像探索を省略すること
- 画像が必要なのに、表示方法を書かずに終わること
- Skill の説明をキャラクター本文にそのまま写すこと
- 説明だけで終わって、下書きを作らないこと

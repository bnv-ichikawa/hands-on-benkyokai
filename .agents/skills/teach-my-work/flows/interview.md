# ヒアリング型

材料がない状態から、AIの質問だけで業務を引き出す進め方。**聞き取った内容が唯一の材料になる。**

前提と共通ルールは [SKILL.md](../SKILL.md) にある。ここには段取りだけを書く。

## 段取り

### 1. 業務の輪郭を決める

まず**1つの業務に絞る**。「経理業務」のように大きい場合は、その中の1つに絞る提案をする。

絞ったら、その業務の呼び名をユーザーの言葉で確定させる。以降その名前で呼ぶ。

### 2. ブロックごとに聞く

**1ブロックずつ聞く。5つのブロックを1メッセージに詰め込まない。** 各ブロックは最大5問。

ブロックが終わるたびに、聞き取った要点を短く返して確認する。ここで訂正が入ることを前提にする。

| ブロック | 聞くこと |
| --- | --- |
| 1. 目的と全体像 | 何のための業務か / 結果を誰が受け取るか / どのくらいの頻度で発生するか |
| 2. 開始と完了 | 何をきっかけに始まるか / それはどこに届くか / 何をもって終わりとするか / **終わったとどうやって分かるか** |
| 3. 手順 | 実際にやっている順番。各ステップで**どこを開いて、何を、どうするか**まで。システム名、DB名、URLを取る |
| 4. 判断基準 | どこで迷うか / 何を見て決めるか / **境目の条件や金額** / 誰に確認するか / 自分の裁量はどこまでか |
| 5. 例外と失敗 | うまくいかないケース / そのときどうするか / 判断できないときの相談先（役割名で） |

**ブロック3と4は飛ばせない。** 手順と判断基準が「到達基準」の中心にある。用途によって変えるのは説明の量だけで、聞く深さは変えない。

ブロック1と5は、業務の成否に効く範囲で短く済ませてよい。

#### 各ブロックで1問で終わらせない

最初の答えはほぼ抽象的に返ってくる。**同じ論点を1〜2回追撃して具体化する。** これが深掘りの実体。

- 「請求書を確認します」→「どこで開きますか」→「何を見て、OKかNGかを決めますか」
- 「大きい金額は承認をもらいます」→「大きいの境目は何円ですか」
- 「担当に連絡します」→「どの担当ですか。どの手段で連絡しますか」

追撃も5問に含める。答えが具体的になった時点で次へ進む。判定は [SKILL.md](../SKILL.md) の「実行できる状態の7要素」と「掘るのをやめる条件」を使う。

### 3. 全体をまとめて返す

5ブロックを1つの流れとしてまとめ、1度だけ返す。ここで初めて全体像がユーザーの目に入る。

抜けと違和感を指摘してもらい、必要なら追加で最大5問聞く。

### 4. 配置提案

置き場所とファイル名を提案し、理由を一文で示す（[SKILL.md](../SKILL.md) の「配置」）。合意を取ってからファイルを作る。

### 5. 下書き

[SKILL.md](../SKILL.md) の「書き方」に従う。`source_notes` は「本人からの聞き取り（YYYY-MM-DD）」とする。

会話の中で出た資料名、Notion ページ、Slack チャンネルは、根拠資料として名前とリンクを残す。

### 6. 解像度チェック

[SKILL.md](../SKILL.md) の「解像度チェック」を最低1周回す。

**この進め方では特に必要になる。** 材料がないため、会話で聞いた気になっていて実際には書けていない箇所が出やすい。

### 7. 教え返し

[SKILL.md](../SKILL.md) の「教え返し」に従う。

### 8. 差分確認

[SKILL.md](../SKILL.md) の「差分確認」に従う。

### 9. 成果物化

依頼があれば行う（[SKILL.md](../SKILL.md) の「成果物化」）。

## この進め方での注意

- ブロックを飛び越えて先の話を聞かない。順番に意味がある。目的が分からないまま手順を聞くと、何が重要か判断できない
- 答えにくそうなときは、**例を出すのではなく質問を分解する。** 例を出すとその例に寄った答えが返る
- 「普通は〜ですよね」でAIが埋めない。埋めた内容は事実として保存されてしまう
- ユーザーが「特にない」と答えたことは、空欄ではなく「特にないと確認済み」として扱う
- **抽象的な答えをそのまま次のブロックへ進めない。** 具体化の追撃を先に済ませる
- **ユーザーが面倒がっても、ブロック3と4は削らない。** 分量が多いときは今日はここまでにする提案をする（[SKILL.md](../SKILL.md) の「1回のセッションで終わらなくてよい」）
- 全ブロックが終わる前に下書きを始めない
- 話が別の業務に広がったら、いま扱っている業務を確認し、別ノートにするか後回しにするかを聞く
- ユーザーが長く話し始めたら、無理にブロックへ戻さない。話を受け止めてから、[flows/braindump.md](braindump.md) に切り替えるかを聞く

## 固有の完了条件

[SKILL.md](../SKILL.md) の完了条件に加えて、次を満たしていること。

- **ブロック3（手順）と4（判断基準）を扱っている。** 省いていない
- 各ブロックで、抽象的な答えを具体化する追撃を行っている
- ブロックごとの要点確認をユーザーが済ませている
- **手順の各ステップに、開く場所と具体的な操作が書かれている**
- **判断の分かれ目が、条件・閾値・確認相手の形で書かれている**
- `source_notes` が「本人からの聞き取り（日付）」になっている

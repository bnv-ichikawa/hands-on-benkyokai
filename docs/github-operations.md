# GitHub運用ルール

このリポジトリで変更を行い、Pull Request（PR）を作成・マージするときのルールです。

## `main` へ直接pushしない

`main` へ直接pushしません。変更するときは作業用ブランチを作成し、PRを通して `main` へマージします。

- ブランチ名の先頭に変更の種類を付け、内容が分かる名前にする（例：`docs/`、`feat/`、`fix/`、`chore/`、`ci/`）
- PRのタイトルは、何が変わるのか分かるように書く
- マージ前にレビューを受ける
- ブランチ保護ルールを設定できる場合は、`main` へのPR必須化と必須ステータスチェックを有効にする

## 1つのPRを1つの目的に絞る

1つのPRには、同じ目的の変更だけを含めます。目的の異なる変更は、別のブランチとPRに分けます。

レビュー中に今回の目的と関係のない修正が必要だと分かった場合は、原則として別のIssueまたはPRで対応します。

## PRテンプレートに従う

PRを作成するときは [`.github/PULL_REQUEST_TEMPLATE.md`](../.github/PULL_REQUEST_TEMPLATE.md) に従います。

PRの本文には、少なくとも次の内容を書きます。

- 何が問題で、このPRによって何が変わるか
- 具体的な変更内容と、その変更を選んだ理由
- 実施した動作確認とその結果
- レビューで特に確認してほしい点

動作確認をしていない項目は、確認済みのように書かず「未確認」と明記します。

## マージ前に確認する

- 必要なテストや手動確認が完了している
- READMEやドキュメントを追加・移動した場合、関連する案内とリンクが正しい
- レビューの指摘へ対応した。対応しない指摘がある場合は、その理由をPRに記録した
- 新しいライブラリや依存関係を追加した場合、`npm audit` など適切な方法で脆弱性やセキュリティ上の懸念がないことを確認した

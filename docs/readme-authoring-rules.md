# README の書き方

このファイルは、このリポジトリ内の `README.md` に何を書くか、どこまで書くかを定める固定ルールです。

README は、そのディレクトリに入ってきた人の案内板として扱います。初めて読む人が、その場所の目的・構成・基本的な使い方を短時間で把握できることを優先します。

## 基本原則

### 1. README はそのディレクトリ自身を説明する

README には、そのディレクトリが何を担当する場所なのか、その配下がどのように分かれているか、その階層に共通する使い方やルールを書きます。

子ディレクトリの詳細な手順・設計理由・現在の状態まで親 README に再掲しません。必要な場合は子ディレクトリの README へリンクします。

### 2. 親 README は子ディレクトリの目的・責務までを書く

親 README では、子ディレクトリについて次の範囲まで説明します。

- 何を置く場所か
- 何を担当するか
- どのような単位で分かれているか

子ディレクトリ固有の詳細な使い方、運用手順、設計理由、現在の状態、未決事項は、その子ディレクトリ側を正本にします。

### 3. 現在の状態も正本を1か所にする

現在の状態は、その情報を所有する最も近い README にだけ書きます。

たとえば、ある子ディレクトリのスクリプトが未作成であることや設定値が未確定であることを、親 README にも子 README にも書くことはしません。状態が変わったときに更新する場所が増えないようにします。

この考え方は、[CONSTITUTION.md の原則6](../CONSTITUTION.md#2-1つの決まりの正本は1つのファイルに置く) と同じです。決まりだけでなく、現在の状態についても Single Source of Truth を保ちます。

### 4. リンクは必要な文脈に置く

関連ドキュメントを末尾に一覧化することを目的にしません。

読者がその情報を必要とする箇所で、正本となる README、運用ルール、手順書へリンクします。同じリンクを本文と「関連ドキュメント」一覧の両方へ重複して置かないようにします。

### 5. 時点依存の情報を上位へ伝播させない

子ディレクトリの状態が変わるたびに、親・祖父母 README まで更新が必要になる構造を避けます。

親 README に書くのは、長期間変わりにくい目的・責務・構造・共通ルールを中心にします。

## README に書くもの

必要なものだけを選んで書きます。すべての見出しを必須にはしません。

| 内容 | 書くこと |
|---|---|
| 概要 | そのディレクトリが何をする場所か |
| ディレクトリ構成 | 配下の主要なディレクトリと、それぞれの役割 |
| 基本的な使い方 | その階層全体に共通する作業フロー |
| 共通ルール | その README 自身が正本となる、その階層固有のルール |
| 現在の状態 | そのディレクトリ自身が所有する時点依存情報 |
| Goal | そのディレクトリ全体として目指す明確な到達状態 |

## README に書かないもの

| 内容 | 置き場所 |
|---|---|
| 子ディレクトリ固有の現在の状態 | 子ディレクトリの README |
| 子ディレクトリ固有の詳細手順 | 子ディレクトリの README または専用手順書 |
| 既存の運用ルールの再掲 | 正本へのリンク |
| README 本文ですでにリンクしている資料の重複一覧 | 作らない |
| 調査ログ・一時的な確認結果 | 必要に応じて専用ドキュメント |

## 現在の状態を書くとき

`現在の状態` は必要な場合だけ設けます。

書いてよいのは、そのディレクトリ自身が所有する状態です。配下の状態を集約したダッシュボードにはしません。

状態は事実として確認できるものだけを書きます。未確認の内容を推測で埋めません。

## Goal を書くとき

`Goal` は、将来こうなっていたいという「達成状態」を書きます。

たとえば次のように、「〜されている」「〜できる」の形で、達成したかどうかを判断できる表現にします。

```md
## 🎯 Goal

- 自分の業務が、このノートだけで次回実行できる形で残っている
- 決まりの正本が1か所に定まっている
```

運用方針やドキュメントの置き場所など、到達状態ではないものを Goal に混ぜません。

## ディレクトリ構成を書くとき

配下の役割を一言ずつ添えたツリーで示します。この一言は役割のラベルであって、決まりの説明ではありません。

**内部構造を全部展開しません。** 読む人がツリーから知りたいのは「何があるか」で、各所の内訳はその場所の README が持ちます。

## テンプレート

以下はディレクトリ README の基本形です。不要な見出しは削除してください。見出しの絵文字は、内容を素早く判別できる範囲で使います。

````md
# <ディレクトリ名>

`<path>/` は、<このディレクトリが何を管理・担当する場所なのか>です。

<必要であれば、このディレクトリ全体の目的を1〜2文で説明する。>

## 🗂️ ディレクトリ構成

```text
<directory>/
├── <child-a>/    <役割を一言で>
├── <child-b>/    <役割を一言で>
└── <child-c>/    <役割を一言で>
```

### `<child-a>/`

<この子ディレクトリの目的・責務を書く。>

詳細な使い方や現在の状態は [README.md](./child-a/README.md) を参照してください。

### `<child-b>/`

<この子ディレクトリの目的・責務を書く。>

## 🚀 基本的な使い方

<このディレクトリ全体に共通する作業フローがある場合だけ書く。>

1. ...
2. ...
3. ...

<既存の正本となる運用ルールがある場合は、内容を再掲せずリンクする。>

## 📏 共通ルール

<この README 自身が正本となるルールだけを書く。>

## 🚧 現在の状態

<!-- 必要な場合のみ -->

- <このディレクトリ自身が所有する現在の状態>

## 🎯 Goal

<!-- 明確な到達状態がある場合のみ -->

- <このディレクトリ全体として目指す状態>
````

## 判断に迷ったとき

README に書くか迷った場合は、次の順で判断します。

1. その情報は、このディレクトリ自身の目的・構造・共通ルールか
2. 子ディレクトリ固有の情報なら、子側を正本にできないか
3. 時点依存の状態なら、その状態を所有する最も近い README にだけ置けないか
4. すでに正本があるなら、説明を複製せずリンクだけにできないか

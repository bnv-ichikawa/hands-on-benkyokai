# Tools

このディレクトリは、仕事や Second Brain の運用を進めるために、各自のPCで実行するプログラムを置く場所です。

`.agents/skills/` が AI に作業方法を伝える指示を置く場所であるのに対して、`tools/` には実際に実行できるスクリプト、CLI、変換処理、自動化プログラムなどを置きます。

いま入っているのは [`repo-checks`](repo-checks/README.md)（リポジトリの整合性を機械的に検査する）だけです。必要になったときだけ、用途ごとにサブディレクトリを作って追加します。

## 置くもの

- ファイルの変換、整形、抽出を行うスクリプト
- ノートの検索、検査、索引作成を支援するプログラム
- 定型作業を自動化するCLI
- データを集計、分析、出力するツール
- Second Brain や日常業務を補助する小さなユーティリティ

## 基本構成

ツールごとにサブディレクトリを作ります。

```text
tools/
  README.md
  example-tool/
    README.md
    src/
    tests/
    requirements.txt
```

使用する言語や規模に応じて、不要なファイルやディレクトリは省略できます。

## 各ツールに記載すること

各ツールの `README.md` には、少なくとも次の内容を記載します。

- 何をするツールか
- 対応するOSや実行環境
- 必要なランタイムとバージョン
- 依存関係のセットアップ方法
- 実行コマンド
- 入力と出力
- ファイル更新、送信、削除などの副作用
- 必要な環境変数
- 動作確認の方法

実行例:

```sh
cd tools/example-tool
python src/main.py --input example.md
```

実際のコマンドは、各ツールのREADMEを確認します。

## 持ち運べるツールにする

特定のPCだけで動く状態を避けるため、次の点に注意します。

- 個人PCの絶対パスをコードに書かない
- 必要なランタイムのバージョンを明記する
- 依存関係を再現できるファイルを置く
- 初回セットアップ手順を省略しない
- サンプル入力またはテストを用意する
- OS固有の処理がある場合は明記する

## 情報管理と安全性

- パスワード、APIキー、アクセストークンをコミットしない
- 認証情報は環境変数などで渡し、必要なら `.env.example` だけを置く
- 実データや個人情報をテストデータとして保存しない
- 大量更新、上書き、削除、外部送信を行うツールはREADMEに明記する
- 可能であれば、実行前に対象を確認できる `--dry-run` を用意する
- 生成物、キャッシュ、仮想環境、依存パッケージは原則としてGit管理しない

他の人がREADMEだけを読んで、安全にセットアップ、実行、確認できる状態を目指します。

# tools

`tools/` は、**各自のPCで実行するプログラムを置く場所**です。

[`../.agents/skills/`](../.agents/skills/) が AI に作業方法を伝える指示を置く場所であるのに対して、`tools/` には実際に実行できるスクリプト、CLI、変換処理、自動化プログラムなどを置きます。

## 置くもの

- ファイルの変換、整形、抽出を行うスクリプト
- ノートの検索、検査、索引作成を支援するプログラム
- 定型作業を自動化するCLI
- データを集計、分析、出力するツール
- Second Brain や日常業務を補助する小さなユーティリティ

## 🗂️ ディレクトリ構成

ツールごとにサブディレクトリを作ります。

```text
tools/
├── make-pptx/      スライド内容（deck.json）の形式定義
├── marp/           Marp Markdown を PDF / PPTX に変換する
└── repo-checks/    リポジトリの整合性を機械的に検査する
```

新しいツールは、次の形を基本にします。使用する言語や規模に応じて、不要なファイルやディレクトリは省略できます。

```text
example-tool/
├── README.md
├── src/
├── tests/
└── requirements.txt
```

## 📏 各ツールに記載すること

各ツールの `README.md` には、少なくとも次の内容を記載します。

- 何をするツールか
- 対応するOSや実行環境
- 必要なランタイムとバージョン
- 依存関係のセットアップ方法
- 実行コマンド
- 入力と出力
- ファイル更新、送信、削除などの副作用
- 必要な環境変数
- 動作確認の方法

## 📏 持ち運べるツールにする

特定のPCだけで動く状態を避けるため、次の点に注意します。絶対パスの扱いは [CONSTITUTION.md](../CONSTITUTION.md) の「5. 特定のPCでしか動かない状態を作らない」にあります。

- 依存関係を再現できるファイルを置く
- 初回セットアップ手順を省略しない
- サンプル入力またはテストを用意する
- OS固有の処理がある場合は明記する

## 📏 情報管理と安全性

認証情報と個人情報の扱いは [CONSTITUTION.md](../CONSTITUTION.md) の「4. 認証情報と個人情報をリポジトリに入れない」にあります。ツール固有の注意は次のとおりです。

- 認証情報は環境変数などで渡し、必要なら `.env.example` だけを置く
- 実データをテストデータとして保存しない
- 大量更新、上書き、削除、外部送信を行うツールはREADMEに明記する
- 可能であれば、実行前に対象を確認できる `--dry-run` を用意する
- 生成物、キャッシュ、仮想環境、依存パッケージは原則としてGit管理しない

他の人がREADMEだけを読んで、安全にセットアップ、実行、確認できる状態を目指します。
